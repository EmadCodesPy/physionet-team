01 — Context

What We Are Solving

Binary classification: given one overnight polysomnography (PSG) recording per patient, predict whether they will develop cognitive impairment (MCI, Alzheimer's, or dementia) within 3–7 years. Evaluated by AUROC on a hidden test set from a site never seen in training.

Critical constraint Validation and test sets are entirely new sites. Any feature that encodes site-specific recording protocol rather than biology will fail on these sets — even if it looks great in training CV.
Why PSG predicts cognitive impairment Sleep is when the brain clears amyloid-beta and tau proteins via the glymphatic system — the same proteins that accumulate in Alzheimer's. Disrupted sleep architecture means less clearance, which accelerates protein accumulation over years. PSG features that capture sleep disruption are therefore biologically motivated predictors.
02 — Format Discovery

CAISR Annotation Format

Key finding — not what we expected CAISR annotations are NOT stored as discrete events with onset/duration. They are stored as 11 continuous signal channels at 2 Hz. Feature extraction is array operations, not event parsing.

File Specs (verified on I0002 recording)

PropertyValue
Sample rate2.0 Hz — one value every 0.5 seconds
Total samples (6.1 hr recording)43,920
Data shape(11 channels × 43,920 samples)
Annotation count0 — confirms signal-based, not event-based
Human annotation fileSeparate EDF with 4 channels — same 2 Hz format

Channel Inventory and Decoding Strategy

CHANNEL TYPE HOW TO USE
stage_caisr argmax / float noise round → int → decode stage label
caisr_prob_w logit (pre-softmax) apply softmax across 5 prob channels → true probability
caisr_prob_n1 logit (pre-softmax) ↑ same — softmax together with all 5
caisr_prob_n2 logit (pre-softmax) ↑ same
caisr_prob_n3 logit (pre-softmax) ↑ same
caisr_prob_r logit (pre-softmax) ↑ same — R = REM
caisr_prob_arous probability 0–1 use directly — already a probability
caisr_prob_no-ar probability 0–1 complement of arous — 1 − arous ≈ no-ar
arousal_caisr clean binary 0/1 use directly — no transformation needed
resp_caisr float-encoded int round → int → decode respiratory event type
limb_caisr float-encoded int round → int → use cautiously (over-detects vs human)

The five caisr_prob_* channels contain raw logits — unbounded values that go negative and above 10. Applying softmax across all five at each time point converts them to proper probabilities that sum to 1. These probability channels enable uncertainty-aware features that stage_caisr alone cannot provide.

04 — Reliability Assessment

CAISR vs Human Scorer Agreement

Overall sample-level stage agreement: 64.1%. This is typical for automated vs human PSG scoring. However, agreement varies strongly by stage — which means feature confidence varies by stage.

Per-Stage Agreement (derived from cross-tab, I0002 sample)

N2
~87% High confidence
Wake
~82% High confidence
N1
~41% Low confidence
N3
~27% Low confidence
REM
~13% Very low confidence
Important implication for feature engineering N3 and REM agreement is poor. Features derived from these stages (e.g. N3%, REM AHI) are noisier than they appear. This does NOT mean exclude them — N3 and REM are biologically the most important stages for predicting CI. It means: use the probability channels (caisr_prob_n3, caisr_prob_r) to build uncertainty-weighted features rather than relying solely on hard stage labels.
Limb movement — do not use raw counts CAISR over-detects limb movements by approximately 10× compared to human scoring. Raw limb event counts are unreliable. If limb features are used, they must be normalised or engineered carefully. Low priority until resp and stage features are complete.
Note on sample size These agreement figures are from one recording (I0002). They should be recomputed across all training recordings with human annotations before treating them as definitive. The pattern is likely consistent but magnitudes may shift.

Channel harmonisation layer before any feature code Same signal has different names across sites (SaO2 ↔ SpO2, etc.) Hardcoded channel names per site
