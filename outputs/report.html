The 50/50 balance in training is artificial — the organisers deliberately oversampled positive cases. This was done to give you enough positive examples to learn from. However, it creates a serious gap with how the model will actually be evaluated.

Warning — Calibration Gap
A model trained on 50/50 data will learn that cognitive impairment is common. When it sees a population where only 1 in 10 patients has CI, it will be systematically overconfident in predicting positives. Because the evaluation metric is AUROC (which measures ranking, not absolute probabilities), this does not break the score entirely — but it will degrade performance if not addressed. Probability calibration or prevalence adjustment is required before final submission.

Every site is perfectly balanced — S0001 has 242 positive and 242 negative; I0006 has 51/51; I0002 has 18/18. This means you cannot use site as a proxy for any label signal.

Warning — BMI is 37% Missing
BMI is one of only four numeric features available alongside age, sex, and time-to-event. Dropping the 232 records with missing BMI would eliminate 37% of training data — unacceptable. Three options exist: (1) median imputation per site, (2) model-based imputation using age/sex, or (3) encoding BMI as two features: the value itself and a binary "BMI was recorded" flag. Option 3 is recommended as it preserves information about why BMI was missing, which may itself be clinically informative.

The demographics alone are weak predictors. Age is the strongest demographic signal for cognitive impairment — older patients have higher baseline risk. But demographics without PSG features will produce a poor model. They serve best as complementary features alongside signal-derived features.

Critical — S0001 Channel Variability
S0001 accounts for 484 of 622 records — 77.8% of your training data. Its channel count ranges from 11 to 29 within the same site. Any pipeline that hardcodes a fixed set of input channels will crash or produce NaN features for a large fraction of training data. The pipeline must handle missing channels gracefully at every step, from loading through feature extraction.
Good — Recording Durations are Consistent
All sites produce recordings of approximately 7–8 hours. This is expected for overnight PSG studies. Duration variability is low and not a concern for feature engineering. Features based on "fraction of night" (e.g., % time in REM) are directly comparable across records.

Critical — S0001 Has Essentially No EOG
S0001 averages 0.07 EOG channels per recording. Across 30 sampled files, only about 2 had any EOG at all. EOG (eye movement tracking) is one of the three primary signals used to score REM sleep. Without it, the CAISR automated annotations for REM stage in S0001 recordings are unreliable or absent. Since REM disruption is one of the most studied biomarkers for cognitive decline, any feature built around REM must either use a fallback strategy for S0001 or be explicitly marked as unavailable for those records.

Warning — Channel Harmonisation Must Be Done Before Any Feature Extraction
If your code searches for a channel called SaO2, it will silently fail on I0002 where it is called SpO2. This is not an edge case — it affects every site transition. A channel name mapping table must be built and applied as the very first step in any pipeline. This is a one-time infrastructure task that unlocks everything downstream.

Task Split Recommendations
Concrete workstreams for team assignment, ordered by dependency

P1 — Must complete before anything else

P1
Channel Harmonisation Layer
Build a mapping table that normalises all channel name variants to a standard set. Apply it as the first step in every EDF load. Extend the map by inspecting the supplementary set (I0004, I0007) to catch new naming conventions from unseen sites. Without this, no feature extraction code is portable across sites.
INFRA
P1
Supplementary Set EDA
Run the same EDA script on I0004 and I0007 supplementary files. Document which channels exist, their naming conventions, sampling rates, and how they differ from training. This is the only intelligence you have on the hidden test domain. It informs every modelling decision.
DATA

P2 — Core feature engineering

P2
CAISR Annotation Feature Extraction
Extract tabular features from the pre-computed CAISR annotations: sleep stage percentages (W/N1/N2/N3/REM), apnea-hypopnea index (AHI), arousal index, limb movement index, sleep efficiency, sleep latency. These annotations are available for all sets including validation and test — making them the most reliable and portable feature source in the entire dataset.
ML
P2
BMI Imputation Strategy
37% of BMI values are missing. Decide and implement an imputation strategy: (a) site-stratified median, (b) regression using age and sex, or (c) encode as value + missingness indicator. Option (c) is recommended. Implement before any modelling begins so the feature set is stable.
DATA
P2
ECG / HRV Feature Extraction
ECG is present across all three training sites. Heart rate variability (HRV) during sleep reflects autonomic dysfunction, which is an established early biomarker of neurodegeneration. Extract time-domain HRV features (SDNN, RMSSD) and frequency-domain features (LF/HF ratio) using MNE. This is the highest-value raw signal task given ECG's availability across all sites.
ML

P3 — Model and validation

P3
Baseline Model + Site-Stratified CV
Train a gradient-boosted tree (XGBoost or LightGBM) on tabular features only: demographics + CAISR-derived statistics. Use site-stratified cross-validation — never mix sites within a fold, since the held-out sets are entirely new sites. A model that validates across sites is genuinely robust. One that doesn't is overfitting to site-specific artefacts.
ML
P3
Prevalence Calibration
Adjust model output probabilities for the 50/50 train vs. 5–15% real-world prevalence gap. Apply prior correction using Bayes' theorem before scoring. Implement as a post-processing step that can be tuned without retraining the model. Test its impact on AUROC on your leave-one-site-out validation.
STRATEGY
P3
EEG Spectral Features (if EOG missing)
For S0001 records where EOG is absent, REM detection must fall back to EEG alone. Compute spectral power bands (delta 0.5–4 Hz, theta 4–8 Hz, alpha 8–13 Hz, sigma 12–15 Hz) from EEG channels. Sigma power (sleep spindles) and delta power (slow-wave sleep) are cognitively relevant even without REM information. Treat this as a lower-priority task until CAISR features are validated.

Strategic Summary
The three bets this EDA forces you to make
BET 01 — ROBUSTNESS OVER ACCURACY
Build for missing channels from day one. A model that works on 11-channel and 29-channel recordings is more valuable than one that works only on the full set. The test site (I0007) is unknown — it may have fewer channels than anything in training.
BET 02 — ANNOTATIONS BEFORE RAW SIGNALS
CAISR annotations are pre-computed for all sets. Extracting features from them is faster, more portable, and site-agnostic than processing raw EEG. Start here. Raw signal processing is an enhancement, not a foundation.
BET 03 — VALIDATE ACROSS SITES, NOT WITHIN
Standard random cross-validation will give you falsely optimistic scores because sites have correlated characteristics. Use leave-one-site-out validation. If your model can't generalise from S0001 to I0002 to I0006, it will not generalise to I0004 or I0007.
